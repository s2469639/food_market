# Market Compass 기획 위험 검토안

검토 기준: 현재 project.md, 기존 정량 코드, 호주·일본 수작업 조사 기록, 아래 API 공식 문서.
초안은 제안 문서로 작성했으며 기존 다섯 가지 차별성·문제 정의는 유지한다.
최초 검토 시 project.md와 코드를 변경하지 않았고 새 API의 인증·유료 호출·성능 시험도 하지 않았다.
이후 사용자 피드백으로 승인된 방향은 아래에 구분하고 project.md에 반영했다. 코드는 수정하지 않았다.

## 후속 승인 상태

- 1번: A의 광역 소비 탐색과 C의 공개 다국가 자료를 결합하고 현지어 검증으로 연결한다.
- 3번: 통계 시장 지표와 구체적인 제품 기회를 분리하는 A를 채택하고 국가별 상세 범위 검증 B는 후속으로 둔다.
  국가마다 세분 수준이 달라 같은 수준의 세부 통계를 확보할 수 있다고 가정하지 않는다.
- 4번: 세 상태를 구분하는 A의 방향을 승인했다. 충분성·전환·명백한 부적합 표시의 세부 규칙은 후속 결정이다.
- 6번: 단계별 검증을 거친 단일 에이전트 MVP A의 방향을 승인했다. 구현 승인은 아니다.
- 추가 예외: 가상 제품 성분·배합을 사용한 프로토타입 시험을 허용하되 실제 롯데 제품 정보와 분리한다.
  실제 시장·규제 데이터나 출처를 생성하는 허용은 아니다. 실제 제품 정보로도 분석할 수 있어야 한다.
- 2번과 5번은 후속 묶음 제안에서 승인됐다. 공통 기본 조사와 자료 부족 후보의 제한적 보완 조사,
  선정·미선정 사유 기록, 초기 AI 선정안의 사람 검토를 채택한다. 보완 조사 한도와 검토 범위는 시험 후 결정한다.
  사업 기반·제품 판매·공급 방식을 분리하고 각 출처·시점·확인 상태를 기록한다.
  기반 존재와 실제 활용 가능성을 구분하며, 미확인 활용은 가설로 남긴다.
  기존의 후보 합집합·최대 6개국·진출 현황 미확인 처리 등 확정 원칙은 그대로 유지한다.

이하 본문은 최초 검토 제안의 근거이며 승인 범위는 이 목록과 최신 project.md를 따른다.

- 확정: 두 경로의 후보 합집합, 넓은 탐색 후 최대 6개국 심층 조사, 경로별 고정 할당 없음,
  제품·소비 근거 연결, 규제·기회 분리, 최소 근거와 보류 원칙, 현 제품 TOP 3와 제품 조정 가설 분리.

## 1. 소비 트렌드 기반 국가 발굴

### ① 현재 문제

국가별 현지어 검색을 처음부터 하려면 조사 국가·언어를 선택해야 한다.
통계 상위국만 검색하면 소비 경로는 사후 검증으로 축소된다.
반대로 ‘국가를 입력하지 않음’이 ‘전 세계를 편향 없이 관찰함’을 뜻하지는 않는다.
검색엔진의 색인·언어·접근 편향은 여전히 남는다. 서로 다른 API를 쓴다고 두 경로가 독립적인 것도 아니다.

### ② 구현 영향

영어권·자료가 풍부한 국가에 편중될 수 있고, 전 세계 SNS 실시간 전수조사를 암묵적으로 약속하게 된다.
언론사 소재국·게시 언어·시청 가능 지역을 실제 소비국으로 잘못 연결할 위험이 있다.

### ③ 대안

A. **광역 탐색 → 국가 추출 → 현지어 검증.** 제품군·특성·소비 상황으로 국가 제한 없는
검색과 다국가 공식·산업 보고서를 탐색한다. 본문에 실제로 소비·판매가 관찰된 국가와 근거 구절을 추출한다.
그 국가의 현지어로 추가 조사한다. 통계 후보 목록을 소비 탐색의 입력 조건으로 사용하지 않는다.

B. 통계 순위와 독립적인 국가·언어 목록을 만들고 지역을 순환하며 가벼운 검색을 수행한다.
국가를 시스템이 지정하는 방식임을 공개한다. 수동 순위 선택을 피할 수 있으나 호출 비용이 커진다.

C. 공개 다국가 보고서·승인된 자료 모음에서 국가를 추출하는 제한적 소비 탐색으로 시작한다.
범위는 좁지만 통계 후보 밖의 국가도 들어올 수 있다. 자료 수집 자동화와 국가 발굴의 독립성을 구분한다.

### ④ 추천

MVP는 A를 기본으로, 편향 점검용 소규모 B를 검토한다. 광역 탐색과 국가별 심층 검증은 같은 소비 경로 안의
서로 다른 단계다. 두 경로의 ‘병렬’은 후보 발견 경로를 독립적으로 운영한다는 뜻이지 모든 처리를 동시에
실행해야 한다는 뜻은 아니다. 원문 국가 연결이 확인되지 않으면 국가 후보로 확정하지 않는다.

독립 소비 탐색에서 신규 후보를 못 찾은 실행도 숨기지 않는다. 신규 국가 수를 보장하거나 억지로 채우지 않는다.
통계에 없는 후보를 받아들일 수 있는 절차가 있는지, 실제로 어떤 경로에서 발견됐는지로 차별성을 검증한다.
독립 탐색의 성과는 ‘통계 외 후보 수’뿐 아니라 원문 근거의 관련성·다양성·누락 범위로 확인한다.

## 2. 최대 6개국 심층 조사 선정

### ① 현재 문제

‘근거와 다양성을 고려’만으로는 같은 입력에서 같은 후보가 선정된다는 보장이 없다.
자료량·LLM의 설명 용이성이 제품 기회의 크기를 대신할 수 있다.

### ② 구현 영향

신흥시장이 조기 탈락하고 유사 기사 반복이 근거의 강도로 오인될 수 있다.
6개국 밖 후보가 ‘기회 없음’으로 잘못 표시될 수 있다.

### ③ 대안

A. **통합 후보별 기본 조사 기회를 제공한 뒤 명시적 기준으로 선정.** 국가×제품군/기회 가설 기준으로
중복을 통합하고 경로·근거를 보존한다. 핵심 출처 확인·제품 관련성·대상국·시점·기회의 구체성을 확인한다.
서로 다른 가설·시장·발견 경로를 검토해 중복되는 조사 대상을 줄이고 선정 근거를 기록한다.
자료가 부족하지만 직접적인 신호가 있는 후보에는 보완 검색을 제공한다.

B. 통계/소비 경로별 고정 자리를 배정한다. 편향을 줄일 수 있으나 이미 합의한 ‘고정 할당 없음’과 다르므로
채택하려면 별도 변경 승인이 필요하다. 이번에는 추천하지 않는다.

C. 선정안을 사람이 확인하고 6개국을 확정한다. 초기 검증에는 유용하지만 최종 목표인 자동 탐색의 대체물은 아니다.

### ④ 추천

A를 기획하고 초기 검증에서 C로 선정의 타당성을 점검한다. 최종 점수·매출 추정은 사용하지 않는다.
문서 수를 합산하지 말고 독립 원자료 단위로 판단한다. 최소 조사 기회는 동일한 검색 횟수만을 뜻하지 않으며
언어·접근 차이를 고려한 보완 한도와 실행 가능한 호출 상한을 함께 정해야 한다.

기록 제안: 국가·제품군·발견 경로·가설·근거 ID·품질 확인·수행 검색·접근 실패·선정 여부·사유·규칙 버전.
사유는 ‘근거 확인 후 선정’, ‘자료 부족으로 추가 확인’, ‘동일 기회 중복’, ‘이번 실행 조사 한도’,
‘범위 불일치’, ‘구체적 반대 근거’ 등으로 분리한다. 자료 부족과 기회 부족을 같은 코드로 기록하지 않는다.
‘기회 부족’ 역시 확인된 반대 근거에 기반해야 하며 미선정은 국가의 영구 제외가 아니다.
검토자·선정 시각과 동률 처리도 남긴다. 세부 우선순위는 사용자와 결정한다.

### ⑤ 추가 확인

같은 후보 묶음으로 선정안이 반복 가능한지, 자료가 적은 후보에 실제 보완 검색이 수행됐는지,
언어·지역·경로별 편향이 있는지 점검한다. 기본 검색 예산·중복 기준·동률 규칙·대체 후보 처리 방식은 미정이다.

## 3. HS 코드와 실제 제품

### ① 현재 문제

공식 ‘달콤한 비스킷’ 설명은 통관 분류 판정이 아니다. 코팅·충전·배합·제조공정·국가별 세번에 따라
확인이 필요하다. H6라는 버전 표기가 같아도 개별 제품 시장의 포괄 범위까지 같다는 뜻은 아니다.

### ② 구현 영향

다른 품목 시장을 비교하거나 HS 성장률을 빠다코코낫 수요 증가로 잘못 제시할 수 있다.
190590 전체를 단순 추가하면 다른 베이커리까지 섞이거나 중복 집계될 수 있다.

### ③ 대안

A. **국제 비교 가능한 HS 시장 지표와 제품별 기회 근거를 분리.** 제품→국가별 세번의 매핑 상태를
확인/잠정/미확인으로 두고, 코드·버전·설명·근거·포함/제외·통계 집계 레벨을 기록한다.
동일 6단위 비교도 제품 포괄성이 확인되는 범위에서만 해석한다.

B. 국가별 세부 세번의 동등한 품목 묶음을 만든다. 가장 정밀할 수 있지만 국가별 상세 통계·연계표가 필요하다.
정의가 다르면 묶음의 동등성을 입증해야 하며 더한 뒤 자동 비교하지 않는다.

C. 코드를 1905 등 상위로 넓힌다. 확보는 쉬워질 수 있지만 제품 구체성은 더 약해지므로 핵심 비교 대안으로 비추천.

### ④ 추천

A로 시작하고 비교에 결정적인 국가만 B를 수작업 검증한다. 제품 규격·공식 분류 자료가 없으면
190531을 작업 가설로 유지하고 확정 매핑처럼 사용하지 않는다. 필요하면 공식 사전심사 등 별도 확인을 검토한다.
국가별 통계는 보고국/교역상대국, 수입 흐름·재수입, 달력/회계연도, HS 버전, 금액·중량 단위,
평가 기준·집계/추정 플래그를 대조한다. 세계 합계와 상대국 합계를 중복 합산하지 않는다.
명목 금액 증가와 물량·가격 변화를 구분하고, 단위가 일치할 때만 단위가치를 계산한다.

### ⑤ 추가 확인

빠다코코낫의 해당 규격 원재료·코팅/배합·제조·수출 정보, 국가별 분류 근거와 공식 연계표가 필요하다.
기존 조사에서 일본 협회 수입 범위는 190531000+190590312였으며, 2021 응답은 H5·이후는 H6였다.
어느 쪽도 자동 합산·연결의 근거가 되지 않는다. 현재 모듈은 이를 아직 해결하지 않는다.

## 4. 추천 가능·추가 검증 유망·분석 보류

### ① 현재 문제

‘완전한 자료가 있는 국가만 추천’은 자료가 풍부한 국가를 유리하게 할 수 있다.
반대로 유망 신호만으로 TOP 3를 채우면 기존 최소 근거 원칙을 깨게 된다.

### ② 구현 영향

자료 공백이 낮은 수요로 오인되거나, 중대한 규제 불확실성이 일반적인 정보 누락과 섞인다.
국가 전체를 하나의 상태로만 표시하면 특정 제품·규격의 문제를 과잉 일반화한다.

### ③ 대안

A. **국가×제품/규격×기회 가설 단위로 세 상태를 관리**하고 시장 기회·근거 완성도·진입 부담을 별도 표시한다.
B. 모든 자료가 갖춰진 경우만 표시한다. 단순하지만 신흥시장의 가능성을 숨긴다.
C. 잠정 추천까지 TOP 3에 혼합한다. 기존 ‘근거 부족으로 TOP 3를 억지로 채우지 않음’과 충돌해 비추천.

### ④ 추천: A의 최소 판정안

| 상태 | 최소 조건 제안 | 결과 사용 |
|---|---|---|
| 추천 가능 | 비교에 필요한 통계 범위·기간 확인, 직접 확인한 구매/판매 또는 소비조사 근거, 실제 제품 특성과 수요 연결, 주요 규제·검역·표시·보관 등 검토 및 치명적 미확인 사항 없음 | 최종 순위 평가 대상 자격. 추천 보장이나 수입 허가·수익 보장 아님 |
| 추가 검증 유망 | 대상국·제품 관련성이 있는 원문 신호와 구체적인 가설은 있으나 일부 통계·구매·제품·경쟁 등 필수 근거가 부족함. 판단을 막는 중대한 충돌·규제 불확실성은 별도 판별 | TOP 3와 분리해 조사할 이유·부족 항목·다음 확인 작업 표시 |
| 분석 보류 | 기회 판단을 바꿀 출처 충돌, 제품-HS 범위의 중대한 불확실성, 핵심 원재료 부재로 수입 가능성 판단 불가 등 | 해당 판단 또는 해당 기회의 최종 추천 보류. 확인 가능한 조사까지 모두 멈추지는 않음 |

‘추천 가능’은 모든 상업 조건을 완벽히 안다는 뜻이 아니다. 비핵심 미확인 항목·경쟁·가격의 한계는 공개할 수 있지만
추천 결론을 뒤집을 미확인 제약은 남겨둔 채 통과시키지 않는다. 무엇이 핵심인지 제품·국가별 확인표로 정해야 한다.
‘추가 검증 유망’은 유망성을 입증한 등급이 아니라 원문 신호에 기반한 조사 우선 가설임을 화면에 명시한다.
링크만 있거나 언급만 있는 국가는 자동으로 ‘유망’이 아니다.

확인된 수입 금지 등 명백한 부적합은 단순 자료 부족과 다르다. 세 상태만으로 이를 감추지 않도록
별도의 ‘현재 조건상 추천 제외’ 사유를 둔다. 네 번째 표시 상태를 만들지/사유 필드로 표현할지는 미정이다.
기존 최소 3개년 미확보에 대한 성장 평가 보류 원칙과 전체 추천 자격의 관계도 명시적으로 결정해야 한다.

### ⑤ 추가 확인

실제 두 국가 사례로 상태 판정과 보류→재검토 전환이 일관적인지 확인한다.
출처의 관련성·조사 대상·표본·시점·원문 확인을 검토하되 ‘출처 N개’만으로 충분성을 정의하지 않는다.
핵심 미확인 사항 목록, 후보의 진입·전환·재검토 절차는 아직 미정이다.

## 5. 기존 진출과 제품군 판매

### ① 현재 문제

현지 법인·공장·다른 제품 판매는 선택 제품군의 판매나 그 기반을 활용할 권한·능력의 증거가 아니다.
기업명·계열 관계를 혼동하거나 과거 판매를 현재 판매로 해석할 위험도 있다.

### ② 구현 영향

‘법인이 있으니 추가 수출이 쉽다’, ‘제품 페이지가 없으니 신규 진출’ 같은 잘못된 결론을 낼 수 있다.
현지 생산제품이 이미 공급되는 경우 한국발 추가 수출의 기회와 충돌할 수도 있다.

### ③ 대안

A. **사업 진출·제품군 판매·제품/규격 판매를 별도 사실로 관리.** 각 사실에 확인 상태·시점·지역·채널·기업 주체·출처를 둔다.
B. 국가별 진출 여부 Boolean 하나만 둔다. 단순하지만 오판 위험이 커 비추천.
C. 사람의 확인 목록을 먼저 쓰고 추후 자동화한다. A의 초기 입력 방식으로 병행 가능하다.

### ④ 추천

A+C. 최소 구조 제안:

- 사업 사실: 국가, 정확한 법인/브랜드 주체와 관계, 법인/생산/수입·유통 등 기반 종류, 확인 상태, 기준일·출처.
- 판매 사실: 국가, 제품군, 제품·규격(알면), 채널, 판매 확인/과거 판매/미확인,
  한국 수출/현지 생산/공급 방식 미확인, 기준일·출처.
- 기회 가설: 목표 소비층·제품군·채널 등 기회 내용, 연결 근거, 기반 활용 가능 가설, 실제 활용 확인 여부, 반대 근거.

‘미확인’은 false가 아니다. 공개 온라인 판매 목록도 제품 혼동·병행수입·품절·게시 시점 등을 확인한다.
회사 공시의 사업 기반이 제품군 판매를 자동으로 확정하지 않는다.
판매 여부를 확인하지 못하면 기존에 합의한 ‘진출 현황 확인 필요’를 유지한다.
기존 사업은 확인됐지만 제품군은 미확인이면 ‘확대 기회 가설’로 조사할 수 있으나 유형을 확정하지 않는다.
공식적으로 특정 범위의 미판매가 확인돼도 그 시점·채널 밖까지 일반화하지 않는다.

제품군이 이미 판매 중인 경우 새 소비층·채널·제품 라인의 확대가 실제 기회인지 따로 입증한다.
사업 기반 활용 가능성만으로 진입 부담을 낮추지 않는다. 제품 수요·규제·공급 방식·경쟁을 별도 검토한다.

### ⑤ 추가 확인

정확한 기업 주체·해외사업 공시, 공식 제품/유통 자료, 최근 판매 목록과 공급 방식이 필요하다.
롯데라는 이름이 같다는 이유만으로 동일 사업 주체로 연결하지 않는다.
공개자료로 유통망 공유·계약·설비 활용을 확인할 수 없으면 가설로 남긴다.

## 6. 전체 현실성

### ① 현재 문제

목표의 방향은 타당하지만 ‘전 세계 현지 SNS 탐색·제품 적합성·규제 검증·순위’가
하나의 LLM 호출로 자동 해결되는 것으로 이해하면 범위와 신뢰성을 동시에 잃는다.

### ② 구현 영향

시간보다 원문 접근·이용 허가·수출 규격·자료 품질이 병목이 될 수 있다.
병렬 호출로 한도 초과, 번역·재검색·긴 문서의 비용 증가, 출처를 잘못 연결한 설명 생성 위험이 있다.
외부 문서의 지시문을 도구 실행 명령으로 취급하는 위험도 있으므로 문서는 증거 데이터로만 다뤄야 한다.

### ③ 대안

A. **단계별 검증을 거친 단일 에이전트 MVP.** 기존 Python 계산 도구를 유지하고
광역 소비 발굴→후보 통합→최대 6개국 근거 검토→자격 판정→순위·화면을 점진적으로 연결한다.
B. 수작업 조사 보고서만 만든다. 검증에는 적합하지만 에이전트 MVP의 최종 대체물은 아니다.
C. 모든 국가·SNS를 한 번에 자동화한다. 권한·비용·검증 범위가 커 MVP로 비추천.

### ④ 추천과 다섯 차별성 유지 여부

A를 추천한다. 공개 데이터 기반 MVP는 조건부로 가능하지만 추천 가능한 국가가 반드시 3개 나온다고 보장할 수 없다.
핵심 기능 중 일부는 아직 실제 접근 시험이 필요하고, 최종 결과가 추가 검증·보류로 끝나도 정직한 성공 실행일 수 있다.

| 차별성 | 유지 조건 |
|---|---|
| 신규+기존 진출국 확대 | 사업·제품 판매 사실과 확대 가설을 분리 |
| 정량+소비 병렬 탐색 | 소비 경로를 통계 후보 목록으로 제한하지 않음 |
| 국가×제품군 | 실제 제품·규격과 현지 세부 수요로 근거 연결 |
| 매력도와 진입 부담 분리 | 기회 점수로 규제 위험을 상쇄하지 않음 |
| 긍정·반대·불확실성 | 원문 연결·광고 제외·충돌 및 미확인 상태 공개 |

기술 난이도: 통계 계산은 중하, 원문 검색·검증·다국어 국가 연결은 중상,
SNS 국가 귀속·광고 판별·국가별 분류·규제 검증은 높음이다.
이 난이도는 통계적 측정치가 아니라 현재 데이터·권한 요구에 대한 설계 판단이다.
Function Calling 단일 에이전트로 시작할 수 있으며 현재 근거로 LangGraph가 필수라는 결론은 없다.

비용은 추정 달러 금액을 확정하지 않는다. 검색 제공자 계약·검색 깊이·원문 추출·번역·LLM 토큰·재시도에 달려 있다.
산식 제안: 검색 호출량×요금 + 원문 추출량×요금 + 모델 입력/출력 토큰 비용 + 선택 플랫폼 접근 비용.
기존 캐시·출처 중복 제거를 활용하고 단계별 호출·토큰 한도, 최대 재시도·중단 시 부분 결과를 정한다.
전체 워크플로의 실패를 막으려고 부족한 근거를 생성하지 않는다. 키는 .env 또는 안전한 환경 바인딩으로 관리한다.

### ⑤ 지금 정할 것 / 자료 시험 뒤 정할 것

**지금의 결정 우선순위**

1. 광역 소비 탐색과 국가별 검증의 분리, 소비 경로의 독립성 정의.
2. 실제 제품·규격과 국가별 통계 범위를 확인하기 전 결론을 제한하는 규칙.
3. 최대 6개국 선정의 기록 항목·기본 조사 기회·자료 부족 분리.
4. 세 상태와 명백한 추천 제외 사유, 핵심 미확인 사항의 취급.
5. 사업 진출/제품 판매/공급 방식의 분리와 추적 구조.

**실제 자료와 소규모 API 시험 이후 결정**

- 국가·언어·검색어·플랫폼 목록, 호출·시간·토큰 예산과 중단·대체 후보 정책.
- HS 연결·국가별 세부 코드, 실제 비교 기간·커버리지.
- 출처 충분성의 세부 요건, SNS 판별 성능과 검토자 개입 범위.
- 후보 컷오프·선정 동률 규칙, 최종 배점·가중치·순위 민감도.

먼저 광역 소비 탐색 A를 승인할지 논의하고, 제한된 공개자료로 통계 후보 밖 국가를
실제로 발견·원문 연결할 수 있는지 시험하는 것이 권고 순서다. 그 뒤 후보 선정과 상태 규칙을 검증한다.
이번 문서 작성은 이 시험이나 구현을 승인·완료한 것으로 해석하지 않는다.
