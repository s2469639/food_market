# Market Compass — MVP 기획서 v1.0

확정 기준일: 2026-11-09

LOTTE AX Challenge 제출 기획을 바탕으로 하는 개인 학습용 웹 프로토타입이다.
이 문서는 대화에서 확정한 MVP 기준을 통합한 개발 기준서다. 과거 제출안의 제품군 2~3개,
직접 구매자료 일률 필수, 미확정 배점 등의 표현은 아래 최신 MVP 결정으로 대체한다.
기획 v1.0 확정은 구현·배포 완료 또는 코드 개발 착수 승인을 뜻하지 않는다.

## 1. 문제와 목표

“시장이 성장하는 곳과 롯데웰푸드의 제품이 성장할 수 있는 곳은 같을까?”

국가별 무역통계와 현지 소비자료를 제품 특성에 연결하여 검토할 가치가 있는 수출 기회를 발굴한다.
사용자가 국가를 미리 지정하는 대신 제품군을 선택하면 AI가 후보국을 탐색한다.
제품별로 유망국가 최대 3개와 이유·반대 근거·불확실성·추가 확인 사항을 제공한다.
기업 내부 데이터는 없으며 실제 공개자료와 접근 가능한 API를 활용한다.

### 유지할 다섯 가지 차별성

1. 신규 국가 진출과 기존 진출국의 제품군 확대 기회를 함께 탐색한다.
2. 무역통계와 소비 트렌드를 별도 경로로 병렬 탐색한 뒤 후보를 통합한다.
3. 국가 자체보다 국가×제품군을 분석하고, 구체적인 제품·규격에 매칭한다.
4. 시장 기회와 진입 부담을 구분한다.
5. 긍정 근거뿐 아니라 반대 근거·데이터 한계·추가 확인 사항을 제시한다.

## 2. MVP 범위

- 첫 제품군: 스위트 비스킷. 통계 조회 대상은 HS 190531이며 제품별 적용 여부는 별도 확인한다.
- 초기 제품: 실제 기존 제품 P01과 가상 신제품 P02, 총 2개.
- 기본 탐색은 국가를 특정 지역으로 제한하지 않는다. 실제 조사 범위·누락·언어 편향을 공개한다.
- 후보 통합 후 한 실행에서 최대 6개국을 심층 조사한다. 기본 탐색 국가 수의 제한은 아니다.
- 결과는 제품별로 분리한다. P02는 가상 입력에 대한 조건부 결과로 표시한다.
- 최종 추천이 3개 미만일 수 있다. 근거가 없는 국가·순위를 생성하지 않는다.

내부 원가·계약조건을 가정한 정확한 매출·ROI 예측, 전 세계 모든 웹/SNS 전수 조사,
모든 국가의 규제 완전 검토는 첫 MVP의 완료 조건이 아니다.

## 3. 사용자 흐름과 화면

1. 제품군을 선택하고 제품 카드·실제/가상 구분을 확인한다.
2. 기본 통계·소비 조사 기간을 확인한다. 상세 설정은 이 두 기간에 한정한다.
3. 탐색을 시작한다. 국가·가중치를 미리 입력하지 않는다.
4. 통계 탐색과 소비 탐색의 상태를 나란히 확인한다.
5. 후보 통합·제품 매칭·진입 부담 검토 상태를 확인한다.
6. 제품별 추천 요약과 추가 검증·보류 결과를 읽고 상세 근거를 펼친다.

진행 화면에는 발견 경로·조사 이유·출처·자료 시점·부족 항목·실패를 표시한다.
중간 후보와 최종 추천을 구분하고, 측정되지 않은 진행률을 임의의 퍼센트로 표시하지 않는다.

## 4. 데이터와 출처 원칙

| 대상 | 주 활용 출처·방법 |
|---|---|
| 무역통계 | UN Comtrade 공식 API, Python·pandas 계산 |
| 소비·시장 | 국가·정부 및 공신력 있는 기관 우선, KOTRA·KATI 등 공개자료 |
| 현지 신호 | 현지어·영문 검색, 허용된 현지 상품정보·기업 발표·보도·소비자 조사 |
| 제품 | 제조사 공식 소개·라벨·규격서. 가상 제품은 가정 ID |
| 규제 | 해당 국가 소관 당국의 공식 규정·절차·제출서류 안내 |

원문에서 직접 확인한 정보만 사실로 기록한다. 검색 미리보기는 원문 탐색 단서다.
통계 계산과 LLM 해석을 구분한다. 검색 관심·구매 의향·개인 경험·실제 판매는 서로 다르게 표시한다.
기업자료는 제품 특성·발표 등에 활용하되 이해관계를 표시하고 광고·협찬 콘텐츠는 제외한다.
자료 개수보다 관련성·품질을 우선하고 동일 원문 재인용을 독립 근거로 세지 않는다.
원문 URL·근거 구절·발행/갱신일·실제 조사 기간·조회일·대상국·제품 범위·한계를 남긴다.
번역과 분석 가설을 구분한다. 자료 충돌은 정의·단위·시점을 대조하고 해소되지 않으면 해당 판단을 보류한다.
최신 출처와 시점을 보여주되 최신이라는 이유만으로 우선 채택하지 않는다.
접근·인용·보관·재사용은 각 출처의 이용 조건을 따른다.

### 현지어와 국가별 검색 서비스

현지어 사용과 현지 주요 플랫폼 사용은 별개로 고려한다.
러시아 Yandex, 일본 Yahoo! JAPAN, 한국 네이버는 검토할 검색 경로의 예시다.
플랫폼의 국가별 중요도·실제 API·허용 접근·비용·색인 범위·원문 접근은 개발 중 검증한다.
국가별 우선 경로를 조정할 수 있도록 설계하되 모든 플랫폼의 직접 연동을 첫 버전의 필수조건으로 두지 않는다.
범용 검색과 공공자료로 시작하고 현지 서비스는 접근 가능한 경로부터 보완한다.
플랫폼 이름만으로 별도 API나 독립적인 검색 색인이 확보된다고 가정하지 않는다.
검색 서비스·질의·언어·대상국·수행 여부·접근 실패를 기록한다.

해당 국가에서 쓰이는 SNS·영상·커뮤니티도 탐색 대상으로 고려한다.
공개·허용 범위에서 확인하며 재게시·광고·일시적 화제성·이용자 편향을 구분한다.
조사하지 못한 플랫폼은 미조사로 남긴다. 언어만으로 실제 대상국을 확정하지 않는다.

## 5. 후보 발굴과 통합

### 무역통계 경로

연간 수입액·수입량 등에서 수입 규모·성장률·수입 증가액을 각각 살펴 후보를 통합한다.
초기 종합점수 하나로 국가를 자르지 않는다. 작은 기준액에서 생기는 높은 성장률도 맥락을 설명한다.

- 기본 기간: 비교 가능한 최근 5개 연도.
- 분류·범위를 연결할 수 없으면 공통 비교 기간으로 줄이되 최소 연속 3개 연도.
- 3개년 미만이면 성장 판단을 보류하고 국가 후보는 유지한다.
- HS 버전·보고국·상대국·연도·통계 범위·원래 보고/추정 여부를 확인한다.
- 국가별 6단위와 추가 세분류를 구분하고 서로 다른 품목 범위를 합치지 않는다.
- YoY = (당해/전년 − 1) × 100, CAGR = ((마지막/첫해)^(1/경과 연수) − 1) × 100.
- 결측은 0이 아니다. 분모 0·필수 연도 누락 등 계산 불가 사유를 표시한다.

HS 수입 증가를 특정 제품의 수요 증가나 롯데 매출 증가로 해석하지 않는다.
서로 다른 기간·품목 범위의 성장률을 그대로 국가 순위에 사용하지 않는다.

### 소비 경로

국가 제한 없는 제품·소비 특성 검색과 공개 다국가 자료에서 국가 단서를 추출한 뒤 현지어로 보강한다.
통계 후보 목록을 필수 입력으로 사용하지 않는다. 기본 조사 기간은 최근 2년이다.
오래된 자료는 기간 밖 보완 자료로 표시하고 조사 기간을 묵시적으로 늘리지 않는다.
맛·식감·원료·영양·섭취 상황·포장 등 HS가 담지 못하는 세부 기회를 찾는다.
제품 특성에서 출발하는 검색과 소비자료에서 출발하는 검색을 병행한다.

관련 간접 신호와 인접 품목 단서도 유지한다. 자료가 뒷받침하는 주장과 아직 뒷받침하지 못하는 주장을 구분한다.
전시·출시·상품 페이지는 실제 구매 실적으로 바꾸지 않는다. 직접 구매자료가 없다고 자동 탈락시키지 않는다.
통계 밖 새 국가 발견은 양쪽 후보 집합을 실제 비교한 경우에만 성과로 주장한다.

### 합집합과 최대 6개국

1. 두 경로 합집합을 만들고 중복 국가의 모든 발견 이유를 보존한다.
2. 대상국·제품 관련성·출처·시점을 공통 확인하고 부족한 부분을 표시한다.
3. 구체적 기회 가설과 서로 다른 시장 규모·성장·소비 기회를 고려한다. 경로별 고정 할당은 없다.
4. 자료가 적다는 이유로 탈락시키지 않고 보완할 질문을 남긴다.
5. 최대 6개국을 선택하고 선택·미선택 이유를 기록한다. 나머지는 이번 조사 범위 밖 후보로 보존한다.

자료 부족·접근 실패·기회 중복·실행 한도·실제 반대 근거를 구분한다.
최종 추천 점수를 후보 압축에 미리 적용하지 않는다. 초기 선정안을 사람과 검토해 편향을 확인한다.

## 6. 제품 매칭

카드 기본형: **제품 속성 → 소비 신호 → 연결 가설 → 반대 근거 → 미확인 사항 → 상태**.

실제 제품의 확인 속성, P02의 가상 입력, 출처에서 확인한 시장 신호, AI의 적합성 가설을 구분한다.
경쟁제품과 공통된 특징은 시장 접점으로 활용할 수 있으나 독점적 차별성·경쟁 우위로 주장하지 않는다.
직접 구매 근거가 없더라도 관련 신호와 구체적 가설이 있으면 후보를 유지한다.
제품 정보 부족은 영향을 받는 판단만 보류한다. 확인된 특성만으로 가능한 탐색은 계속한다.

현재 제품으로 대응하는 기회와 배합·원료 등의 제품 조정이 필요한 가설을 구분한다.
제품 조정 가설은 별도 표시하고 현재 제품의 TOP 3에 섞지 않는다.
통상적인 수출 라벨 변경과 제품 자체 변경의 세부 경계는 실제 사례로 검토한다.

## 7. 평가와 추천

**첫 버전은 공통 질문에 따른 정성 비교이며 배점·가중치를 사용하지 않는다.**
시장 상황·소비 신호·제품 연결·진입 부담·중요한 미확인 사항을 동일한 양식으로 비교한다.
국가별 자료 유형은 달라도 되며 직접 구매자료를 일률적인 필수조건으로 두지 않는다.
간접 신호가 지지하는 범위와 근거 수준을 설명하고 중요한 공백은 추가 검증으로 남긴다.

| 상태 | 판단 기준 |
|---|---|
| 추천 가능 | 제품에 연결되는 기회와 주요 진입 부담을 설명할 근거가 있고, 추천을 바꿀 핵심 미확인이 남지 않은 경우 |
| 추가 검증 유망 | 관련 신호·구체적 기회 가설이 있지만 중요한 자료가 부족한 경우 |
| 분석 보류 | 중대한 자료 충돌이나 미확인 사항 때문에 해당 판단을 진행하기 어려운 경우 |

명백한 금지·부적합은 ‘현재 조건상 추천 제외’ 사유로 표시하고 단순 미확인과 구분한다.
자료가 없다는 사실만으로 불리한 기회 점수나 ‘제약 없음’을 부여하지 않는다.
중대한 규제·진입 불가 조건을 시장 성장으로 상쇄하지 않는다.

제품별 추천 가능 후보에서 최대 3개를 선정하고 국가 간 선택 이유를 설명한다.
유사한 후보의 우열이 불분명하면 동등한 우선 검토 후보로 표시한다.
추천 가능 상태와 TOP 3 선정은 구분한다. 조건을 갖춘 국가가 적으면 적게 출력한다.
P02 결과는 가상 제품 조건부 분석이며 실제 롯데 제품 추천으로 제시하지 않는다.
정성 판단의 일관성·선정 재현성은 첫 실행에서 검증하고 필요성이 확인된 기준만 보완한다.

## 8. 진입 부담과 부족 자료 안내

주요 수입 금지·제한, 인증·표시, 관세, 보관·운송, 경쟁·가격을 검토한다.
중요한 공백마다 다음 정보를 제공한다.

| 항목 | 내용 |
|---|---|
| 부족한 것 | 미확인 정보·자료·서류 |
| 필요한 이유 | 어느 판단을 위해 필요한지 |
| 확보할 자료 | 구체적인 명칭과 포함할 내용 |
| 확보처 | 제조사·수입자·소관 기관 등 |
| 해소 조건 | 무엇이 확인되면 재판정할 수 있는지 |
| 공식 근거 | 적용 국가·제품·절차·규정 출처·시점 |

분석에 필요한 원재료 명세서 등과 실제 수입 절차에서 제출하는 서류는 구분한다.
서류명·필요 여부는 공식 출처에서 확인한 범위로 표시한다.
미확인이면 ‘제출서류 확인 필요’와 확인할 기관을 남기며 이름을 만들어 채우지 않는다.
서류 준비만으로 수입 통과를 보장하지 않는다. 서류 요구 확인·내용 적합성·기관 심사 단계를 구분한다.
최초에는 결론을 바꾸는 주요 사항부터 다루며 모든 규제를 완결하는 절차를 추가하지 않는다.

기업의 국가별 사업 기반, 제품군·개별 제품 판매, 한국발 수출·현지 생산을 별도로 기록한다.
미확인 판매 현황은 미진출이 아니다. 사업 기반이 있어도 공유·활용 가능성을 자동 확정하지 않는다.
기회 유형은 신규 진출 / 기존 진출국 제품군 확대 / 진출 현황 확인 필요로 표시한다.

## 9. 결과 출력

제품별 추천 요약을 먼저 보여주고 상세를 펼친다. 추가 검증·분석 보류는 별도 묶음으로 표시한다.
무역통계와 소비 신호를 나란히, 진입 부담을 별도 영역에 표시한다.
자료가 부족해도 확보한 내용·누락 이유·필요 자료를 함께 보여준다.

상세 영역: ① 시장 기회 ② 제품 적합성 ③ 진입 부담·반대 근거 ④ 불확실성·추가 확인 ⑤ 출처.
전체 비교표·독립 보고서 중심 화면은 후속 확장이다. 실제 가격·시장 수치와 가상 입력을 혼합하지 않는다.

## 10. 기술 방향·보안·저장

- Python·pandas: 기존 조회·정량 계산을 이어 사용한다.
- OpenAI Function Calling 기반 단일 에이전트 우선: 조회·검색·원문 확인 도구와 근거 추출을 연결한다.
- 도구 결과와 구조화 출력의 형식·출처 누락을 검사한다. LLM이 통계 수치를 새로 생성하지 않는다.
- Next.js·FastAPI·Streamlit을 포함한 웹/서버 프레임워크는 미정이다.
- DB 제품도 미정이다. 구현 난이도·데이터 수집·화면·저장 연결 편의성을 개발 시작 때 비교한다.
- LangGraph 등은 분기·재개·오류 복구 복잡성이 실제로 확인될 때 검토한다.
- API·접근·쿼터 오류는 자료 부족과 구분한다. 가능한 부분 결과를 보존하고 신뢰할 수 없는 판단은 멈춘다.
- 저장·재개 후속 설계: 실행 ID, 제품 버전/실제·가상 구분, 조건, 단계 상태, 후보·근거·계산, 실패·누락을 연결한다.
- 전체 저장·DB·재개는 아직 미구현이다. 재사용 유효성·저장 주기 등은 실험 항목이다.
- 비밀값은 실제 `.env` 또는 환경 비밀 설정에 보관한다. `.env.example`은 빈 값의 양식으로 유지한다.
- `.env` 변형·원문 캐시·생성 보고서 등 Git 제외를 유지하고 키를 코드·문서·로그·화면에 출력하지 않는다.

웹 프레임워크와 Python 데이터 수집 기능은 역할이 다르다. Next.js 선택 여부가 Python 수집을 포기한다는 뜻은 아니다.
국가별 플랫폼 접근 가능성도 프레임워크 이름만으로 해결된다고 보지 않는다.

## 11. 실제 구현 상태와 개발 순서

| 구분 | 현재 상태 |
|---|---|
| Comtrade 조회·pandas 성장률 계산·캐시·오류 처리 | 구현됨. 기존 단위 테스트 16개 통과 이력. 이번 문서 작업에서 재실행하지 않음 |
| 제품·소비 사례 | P01 공개 표시 조사, P02 가상 카드, 소규모 수작업 조사·매칭 예시 작성 |
| 자동 소비 검색·국가 후보 통합·제품 매칭·최종 정성 비교 | 미구현 |
| OpenAI 에이전트·웹 화면·DB·전체 저장/재개 | 미구현 |

호주·일본·미국은 기존 연결 시험 국가다. 인도·몽골 등 수작업 사례도 확정 추천국이 아니다.
기획의 최근 5개년/최소 3개년 등과 현재 코드의 세부 허용 조건은 차이가 있으며 개발 시 점검한다.

개발 순서: **데이터 확보 → 에이전트 연결 → 제품 매칭 → 비교 화면**.
첫 개발 목표는 제품 입력에서 두 경로 후보 발굴·통합, 최대 6개국 조사, 제품 매칭,
근거·한계를 담은 결과까지 한 흐름을 연결하는 것이다. 각 단계의 실제 동작을 확인한 다음 확장한다.
실제 결과에서 드러난 문제를 기획에 반영하며, 추가 연구만으로 개발 착수를 계속 미루지 않는다.
